# Contributing to RIGOR

Keep it sharp and honest — the protocol practices what it preaches.

**Great PRs:**
- Tuning files for new models (`protocols/<model>.md`) — where does the model
  fabricate or sycophant, and what one line fixes it?
- New domain modules (`modules/<domain>.md`) — short, principle-based, no fluff.
- Real before/after cases (`examples/`) — actual prompts where RIGOR changed the
  output. Reproducible beats hypothetical.

**House rules:**
- No jailbreaks, no "trick the model" hacks. RIGOR is about rigor, not bypass.
- Every claim in a module is something you'd defend.
- Keep files short. If it's not load-bearing, cut it.
